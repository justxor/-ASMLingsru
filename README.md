## 1. Что такое ASMLings и зачем оно нужно

**ASMLings** — это набор из ~32 коротких упражнений на ассемблере Intel 8086, выстроенных по возрастанию сложности: от `mov ax, 0x1337` до 32-битного сложения через carry flag, циклов, подпрограмм, работы с памятью и стеком.

Что ты получаешь:

- **Мгновенный фидбек.** Сохраняешь файл — через долю секунды видишь результат: прошёл ассерт или нет.
- **Изолированную среду.** Не нужно поднимать MS-DOS, DOSBox или возиться с линковщиком — всё крутится во встроенном 16-битном эмуляторе.
- **Понятную прогрессию.** Каждое упражнение строится на знаниях из предыдущего, и в комментариях прямо в `.asm`-файле уже лежит мини-объяснение темы.
- **Низкий порог входа в системное программирование.** Понимание 8086 — это лучший «букварь» к x86-64, ARM64, ядрам ОС, реверсу, эксплойтам, embedded и тому, что генерит `rustc`/`gcc`.

Для кого: Rust-разработчики, бэкендеры и системщики, которые хотят перестать смотреть на ассемблер из `godbolt` как на магию.

## 2. Как это устроено под капотом

Когда ты сохраняешь `.asm`-файл, ASMLings выполняет следующий конвейер:

1. **NASM компилирует** твой файл в плоский 16-битный бинарь (`flat` формат, без ELF/PE-обвязки).
2. **Rust-эмулятор 8086** загружает этот бинарь в виртуальную память по адресу `_start`.
3. Эмулятор пошагово декодирует и исполняет инструкции, обновляя виртуальные регистры (`AX, BX, CX, DX, SI, DI, BP, SP, IP`), сегментные регистры (`CS, DS, ES, SS`) и `FLAGS`. Исполнение длится до встречи с `hlt`.
4. **Раннер парсит специальные комментарии** `; ASSERT_REG`, `; ASSERT_MEM`, `; ASSERT_FLAG` и сравнивает финальное состояние эмулятора с ожидаемым.
5. Если все ассерты прошли **и** ты убрал строку `; I AM NOT DONE` — раннер переключается на следующее упражнение.

Watch-режим (`asmlings start`) сидит на файловой системе через inotify/FSEvents и пере-прогоняет упражнение при каждом сохранении.

> 🧠 Почему именно 8086, а не x86-64? Потому что 8086 ровно настолько маленький, чтобы за вечер выучить набор инструкций целиком, но при этом достаточно реальный — вся идеология (регистры общего назначения, флаги, стек, сегменты) дошла до современных CPU практически без изменений.

## 3. Установка и зависимости

### 3.1 Что должно быть в системе

| Зависимость | Зачем нужна | Проверка |
|-------------|-------------|----------|
| **Rust toolchain** | поставить и запустить `asmlings` | `rustc --version` |
| **NASM** | компилятор, который превращает `.asm` в бинарь | `nasm -v` |
| (Linux) **libatomic** | нужна Rust-эмулятору для 128-битных атомиков | — |

Если Rust ещё не стоит:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### 3.2 Установка NASM

```bash
# macOS
brew install nasm

# Ubuntu / Debian
sudo apt install nasm

# Arch Linux
sudo pacman -S nasm

# Fedora / RHEL
sudo dnf install nasm

# Windows (PowerShell)
winget install NASM
```

### 3.3 Установка asmlings

**Вариант A — быстро, без компиляции (рекомендую):**

```bash
cargo install cargo-binstall
cargo binstall asmlings
```

**Вариант B — через cargo (с компиляцией всего эмулятора, ~3–5 минут):**

```bash
cargo install asmlings
```

**Вариант C — готовый бинарник:** [Releases](https://github.com/giacomo-folli/asmlings/releases).

### 3.4 Troubleshooting (Linux)

Если `cargo install asmlings` падает с ошибкой линковщика про `__atomic_compare_exchange_16` или `undefined symbol` — твоему линковщику не хватает `libatomic` (Rust-эмулятор использует 128-битные атомарные операции):

```bash
RUSTFLAGS="-Clink-arg=-latomic" cargo install asmlings
```

Если линкер ругается, что `-latomic` не найден — поставь библиотеку:

```bash
# Ubuntu / Debian
sudo apt install libatomic1

# Arch
sudo pacman -S gcc-libs

# Fedora / RHEL
sudo dnf install libatomic
```

После этого повтори `cargo install asmlings`.

## 4. Первый запуск

```bash
# 1. Создай рабочую папку и зайди в неё
mkdir asm-course && cd asm-course

# 2. Развернуть упражнения и трекер прогресса
asmlings init

# 3. Запустить watch-режим — оставь этот терминал открытым!
asmlings start
```

После `asmlings init` в текущей папке появится:

```text
asm-course/
├── exercises/          ← задания (.asm файлы)
│   ├── 01_bare_metal.asm
│   ├── 02_halves.asm
│   ├── 03_addition.asm
│   └── ...
└── .asmlings/          ← трекер прогресса
```

Команды, которые тебе пригодятся:

```bash
asmlings start    # watch-режим: пересобирает текущее упражнение при сохранении
asmlings run      # одноразово прогнать текущее упражнение
asmlings list     # статус всех упражнений (done / todo)
asmlings hint     # подсказка по текущему упражнению (если есть)
```

## 5. Анатомия упражнения

Открой любой файл из `exercises/` — у всех одинаковый каркас. Вот `01_bare_metal.asm` целиком, как он лежит в репозитории:

```asm
; EXERCISE 1: The Bare Metal
; The 8086 CPU has four main general-purpose 16-bit registers: AX, BX, CX, DX.
; Move the value 0x1337 into the AX register.
;
; ASSERT_REG: AX == 0x1337
global _start
section .text
_start:
; Write your code here:
; I AM NOT DONE

hlt
```

Разбираем построчно:

| Строка | Что это |
|--------|---------|
| `; EXERCISE 1: ...` | Описание задачи человеческим языком. |
| `; ASSERT_REG: AX == 0x1337` | **Машиночитаемая проверка.** Раннер прочитает это и сравнит с финальным состоянием регистра `AX`. |
| `global _start` | Делает метку `_start` видимой для линковщика — это точка входа. |
| `section .text` | Секция исполняемого кода. |
| `_start:` | Метка точки входа: эмулятор начнёт исполнение отсюда. |
| `; Write your code here:` | Сюда ты вписываешь решение. |
| `; I AM NOT DONE` | «Сентинель». Пока эта строка есть — упражнение не зачитывается, даже если ассерты прошли. |
| `hlt` | Останавливает CPU. Без него эмулятор будет крутить мусор в памяти. |

### 5.1 Три типа ассертов

```asm
; ASSERT_REG:  AX == 0x1337           ← проверка регистра
; ASSERT_MEM:  result == 0x000F       ← проверка слова в памяти по метке
; ASSERT_FLAG: ZF == 1                ← проверка флага
```

### 5.2 Решение упражнения 1

Чтобы пройти, добавь одну инструкцию и убери сентинель:

```asm
; EXERCISE 1: The Bare Metal
; ASSERT_REG: AX == 0x1337
global _start
section .text
_start:
    mov ax, 0x1337    ; ← наш код
hlt
```

Сохраняешь — в терминале с `asmlings start` пробегает зелёный `Successfully ran exercises/01_bare_metal.asm!`, и раннер переключается на следующий файл.

## 6. Мини-курс по 8086

### 6.1 Регистры общего назначения (16 бит)

| Регистр | Назначение | Половинки (8 бит) |
|---------|------------|-------------------|
| `AX` | **A**ccumulator: арифметика, ввод/вывод | `AH` (high) / `AL` (low) |
| `BX` | **B**ase: адресация (`[bx]`, `[bx+si]`) | `BH` / `BL` |
| `CX` | **C**ounter: счётчик циклов и сдвигов | `CH` / `CL` |
| `DX` | **D**ata: умножение/деление, порты I/O | `DH` / `DL` |

Особенность 8086: каждый из этих регистров можно резать пополам и работать с ними как с двумя 8-битными:

```asm
mov ax, 0x0000
mov ah, 0xAB      ; AX = 0xAB00
mov al, 0xCD      ; AX = 0xABCD   ← это и есть упражнение 02
```

### 6.2 Индексные и указательные регистры

| Регистр | Что хранит |
|---------|------------|
| `SI` (Source Index) | указатель источника для строковых операций |
| `DI` (Destination Index) | указатель приёмника |
| `BP` (Base Pointer) | база стекового фрейма |
| `SP` (Stack Pointer) | вершина стека |
| `IP` (Instruction Pointer) | адрес текущей инструкции (изменяется только переходами) |

### 6.3 Сегментные регистры

8086 адресует память по схеме `сегмент:смещение`. Физический адрес = `сегмент * 16 + смещение`, что даёт 20-битное адресное пространство — 1 МБ.

| Регистр | Назначение |
|---------|------------|
| `CS` (Code Segment) | сегмент текущего кода |
| `DS` (Data Segment) | сегмент данных по умолчанию |
| `ES` (Extra Segment) | дополнительный сегмент (часто для строк) |
| `SS` (Stack Segment) | сегмент стека |

В ASMLings адресация упрощена — для большинства задач достаточно работать со смещениями и метками.

### 6.4 Регистр FLAGS

8086 не возвращает результат сравнения как значение — он выставляет **флаги**, которые затем читают условные переходы.

| Флаг | Имя | Когда взводится |
|------|-----|-----------------|
| `ZF` | Zero | результат операции = 0 |
| `CF` | Carry | беззнаковое переполнение / перенос |
| `SF` | Sign | старший бит результата = 1 (т.е. отрицательное число) |
| `OF` | Overflow | знаковое переполнение |
| `PF` | Parity | чётное число единичных битов в младшем байте |
| `AF` | Auxiliary | перенос между нибблами (для BCD) |
| `DF` | Direction | направление строковых операций (0 = вперёд) |
| `IF` | Interrupt | разрешены ли прерывания |

В упражнениях чаще всего встречаются `ZF`, `CF`, `SF`.

## 7. Синтаксис NASM

### 7.1 Скелет файла

```asm
; Это комментарий — всё после ';' до конца строки
global _start             ; экспортируем точку входа
section .text             ; секция кода
_start:                   ; метка-точка входа
    mov ax, 0x1337        ; инструкции
    hlt
section .data             ; секция данных (необязательно)
counter: dw 0x0000        ; объявляем слово (word, 16 бит)
message: db "Hi", 0       ; объявляем байты со строкой
```

### 7.2 Правила синтаксиса (Intel)

- Порядок операндов: `mov dest, src` — приёмник слева, источник справа.
- Числа: `42` (dec), `0x2A` или `2Ah` (hex), `0b101010` (bin), `'A'` (символ → 0x41).
- Память — в квадратных скобках: `mov ax, [0x0200]`, `mov [bx], cx`.
- Размер операнда задаётся регистром или директивой `byte`/`word`: `mov word [bx], 1`.
- Регистр нечувствителен: `MOV AX, BX` ≡ `mov ax, bx`.

### 7.3 Директивы объявления данных

| Директива | Размер | Пример |
|-----------|--------|--------|
| `db` | 1 байт | `db 0x42, 'A', 10` |
| `dw` | 2 байта (word) | `dw 0x1337, 0xCAFE` |
| `dd` | 4 байта (dword) | `dd 0xDEADBEEF` |
| `resb N` | резерв N байт | `buffer: resb 64` |

### 7.4 Метки и локальные метки

```asm
loop_start:                ; глобальная метка
    inc ax
    cmp ax, 10
    jne loop_start

main:
    mov cx, 5
.again:                    ; локальная метка (видна только внутри main)
    dec cx
    jnz .again
```

## 8. Базовые инструкции с примерами

### 8.1 `mov` — пересылка

```asm
mov ax, 0x1234        ; немедленное → регистр
mov bx, ax            ; регистр → регистр
mov [0x0200], ax      ; регистр → память
mov cx, [0x0200]      ; память → регистр
mov [bx], dx          ; косвенная адресация через регистр
```

Что **нельзя**: `mov [bx], [si]` — память→память за одну инструкцию запрещено, нужно через регистр.

### 8.2 `add`, `sub`, `inc`, `dec`, `neg`

```asm
mov ax, 10
add ax, 5       ; ax = 15
sub ax, 3       ; ax = 12
inc ax          ; ax = 13   (короче, чем "add ax, 1")
dec ax          ; ax = 12
neg ax          ; ax = -12  (дополнение до двух → 0xFFF4)
```

### 8.3 `mul` и `div` — умножение и деление

`mul` всегда использует `AX` как один из множителей, а результат кладёт в **двойную ширину** `DX:AX`:

```asm
mov ax, 6
mov bx, 7
mul bx              ; DX:AX = AX * BX → DX=0, AX=42
```

`div` делит `DX:AX` на операнд, в `AX` идёт частное, в `DX` — остаток:

```asm
mov dx, 0
mov ax, 100
mov bx, 7
div bx              ; AX = 100/7 = 14, DX = 100%7 = 2
```

> ⚠️ Всегда обнуляй `DX` перед `div`, если делишь маленькое число. Иначе делитель учтёт мусор из `DX` как старшее слово и поделит совсем не то.

### 8.4 Логика: `and`, `or`, `xor`, `not`, `test`

```asm
mov ax, 0xF0F0
and ax, 0x00FF     ; ax = 0x00F0   ← маска: оставить младший байт
or  ax, 0x0F00     ; ax = 0x0FF0   ← установить биты
xor ax, ax         ; ax = 0        ← идиома обнуления
not ax             ; ax = 0xFFFF   ← инвертировать все биты
test ax, 0x0001    ; как and, но результат не пишет — только флаги
```

Почему `xor ax, ax` лучше, чем `mov ax, 0`: машинный код короче (2 байта против 3) и быстрее на старых CPU. Это устоявшаяся идиома, которую генерят даже современные компиляторы.

### 8.5 Сдвиги: `shl`, `shr`, `sar`, `rol`, `ror`

```asm
mov ax, 0x0001
shl ax, 1          ; ax = 0x0002  (логический сдвиг влево = умножение на 2)
shl ax, 3          ; ax = 0x0010  (умножение на 8)

mov ax, 0x0010
shr ax, 2          ; ax = 0x0004  (логический сдвиг вправо = деление на 4)

mov ax, 0x8000
sar ax, 1          ; ax = 0xC000  (арифметический сдвиг — сохраняет знак)

mov ax, 0x1234
rol ax, 4          ; ax = 0x2341  (циклический сдвиг влево)
```

### 8.6 `cmp` и условные переходы

`cmp a, b` делает `a - b` **только ради флагов**, результат не сохраняет.

```asm
mov ax, 5
cmp ax, 5
je  equal           ; jump if equal (ZF=1)
jne not_equal       ; jump if not equal
jl  less            ; знаковое <
jg  greater         ; знаковое >
jb  below           ; беззнаковое <
ja  above           ; беззнаковое >
jz  is_zero         ; ZF=1 (синоним je)
jnz is_nonzero      ; ZF=0
jc  carry           ; CF=1
jnc no_carry        ; CF=0

equal:
    mov bx, 1
```

Запомни различие: `jl/jg` смотрят на `SF`+`OF` (для знаковых), `jb/ja` смотрят на `CF` (для беззнаковых). Если перепутать — будут весёлые баги на отрицательных числах.

### 8.7 `loop`

Шорткат для `dec cx + jnz label`:

```asm
mov cx, 5          ; счётчик
xor ax, ax         ; ax = 0
.next:
    add ax, 1
    loop .next     ; cx--, прыгает пока cx != 0
; в результате ax = 5
```

### 8.8 Стек: `push`, `pop`

Стек растёт **вниз** по адресам. `push` уменьшает `SP` на 2 и пишет слово, `pop` читает и увеличивает `SP` на 2.

```asm
mov ax, 0xAAAA
push ax              ; кладём AAAA на стек
mov ax, 0xBBBB
push ax              ; кладём BBBB сверху
pop bx               ; bx = 0xBBBB
pop cx               ; cx = 0xAAAA
```

LIFO как есть. Полезный трюк — обмен через стек:

```asm
push ax
push bx
pop  ax              ; ax получил то, что было в bx
pop  bx              ; bx получил то, что было в ax
```

### 8.9 Подпрограммы: `call` и `ret`

`call label` = `push IP_next; jmp label`. `ret` = `pop IP`.

```asm
_start:
    mov ax, 9
    call double      ; вызов
    ; здесь ax = 18
    hlt

double:
    shl ax, 1        ; умножить на 2
    ret              ; вернуться
```

## 9. Разборы реальных упражнений из репозитория

Ниже — реальный код заданий и одно из возможных решений с объяснением. Не подсматривай раньше времени :)

### Упражнение 2 — Register Halves

```asm
; Set AH to 0xAB and AL to 0xCD so that AX equals 0xABCD.
; ASSERT_REG: AX == 0xABCD
global _start
section .text
_start:
; Write your code here:

hlt
```

**Решение:**

```asm
_start:
    mov ah, 0xAB
    mov al, 0xCD
    hlt
```

Почему работает: `AX` физически — это `AH` (старший байт) и `AL` (младший байт), склеенные в 16 бит. Записывая в половинки, мы собираем `0xABCD` по кусочкам.

---

### Упражнение 3 — Addition

```asm
; Start with BX = 0x0010, then add 0x0005 to it. Result should be 0x0015.
; ASSERT_REG: BX == 0x0015
```

**Решение:**

```asm
_start:
    mov bx, 0x0010
    add bx, 0x0005     ; bx = 0x0015
    hlt
```

### Упражнение 5 — Register to Register

```asm
; Load 0xBEEF into AX, then copy AX into DX.
; ASSERT_REG: AX == 0xBEEF
; ASSERT_REG: DX == 0xBEEF
```

**Решение:**

```asm
_start:
    mov ax, 0xBEEF
    mov dx, ax
    hlt
```

Важно: `mov` копирует, а не перемещает — `AX` не обнуляется.

---

### Упражнение 8 — XOR-обнуление

```asm
; Zero out both CX and DX without using the MOV instruction.
; ASSERT_REG: CX == 0x0000
; ASSERT_REG: DX == 0x0000
```

**Решение:**

```asm
_start:
    xor cx, cx
    xor dx, dx
    hlt
```

`A ^ A = 0` — математическое свойство XOR. Это идиома №1 в ассемблере для обнуления регистров.

---

### Упражнение 10 — Стек

```asm
; Push 0xCAFE onto the stack (via AX), then pop it into BX.
; ASSERT_REG: BX == 0xCAFE
```

**Решение:**

```asm
_start:
    mov ax, 0xCAFE
    push ax
    pop bx
    hlt
```

`push ax` пишет `0xCAFE` по адресу `[SS:SP-2]` и уменьшает `SP` на 2. `pop bx` забирает это слово обратно.

---

### Упражнение 14 — Умножение

```asm
; AX=5, BX=6, then MUL BX. AX should be 30, DX should be 0.
; ASSERT_REG: AX == 0x001E
; ASSERT_REG: DX == 0x0000
```

**Решение:**

```asm
_start:
    mov ax, 0x0005
    mov bx, 0x0006
    mul bx              ; DX:AX = 5 * 6 = 30
    hlt
```

Помни: `mul bx` неявно использует `AX` как первый множитель и пишет результат в пару `DX:AX`.

---

### Упражнение 17 — `cmp` и условный переход

```asm
_start:
    mov ax, 0x000A
    ; Write your code here:
    ; If AX == 0x000A, set BX to 0x0001. Otherwise BX = 0x0002.
```

**Решение:**

```asm
_start:
    mov ax, 0x000A
    cmp ax, 0x000A
    je  is_ten
    mov bx, 0x0002
    jmp end
is_ten:
    mov bx, 0x0001
end:
    hlt
```

Классический if/else через `cmp + je + jmp`.

---

### Упражнение 18 — Цикл

```asm
_start:
    xor ax, ax
    mov cx, 4
    ; Add 0x0003 to AX exactly 4 times → AX should be 0x000C
```

**Решение:**

```asm
_start:
    xor ax, ax
    mov cx, 4
.next:
    add ax, 3
    loop .next         ; cx--, прыгает пока cx != 0
    hlt
```

`loop` сама декрементит `CX` и проверяет на 0 — поэтому `CX` тут одновременно и счётчик, и условие.

---

### Упражнение 20 — Запись в память

```asm
_start:
; Compute 0x0007 + 0x0008 in AX, then store AX into [result].
; ASSERT_REG: AX == 0x000F
; ASSERT_MEM: result == 0x000F

section .data
result: dw 0x0000
```

**Решение:**

```asm
_start:
    mov ax, 0x0007
    add ax, 0x0008      ; ax = 0x000F
    mov [result], ax    ; пишем 16-битное слово по адресу метки
    hlt
```

Здесь интересно: `ASSERT_MEM: result == 0x000F` — раннер сам подставит адрес метки `result` и сравнит лежащее там слово.

---

### Упражнение 23 — Подпрограммы

```asm
_start:
    mov ax, 0x0009
    ; call double — должна удвоить AX → 0x0012
double:
    shl ax, 1
    ret
```

**Решение:**

```asm
_start:
    mov ax, 0x0009
    call double         ; ax = 18 = 0x0012
    hlt
```

`call double` положит на стек адрес следующей инструкции (`hlt`), `ret` в подпрограмме его снимет — и исполнение продолжится с `hlt`.

---

### Упражнение 25 — 32-битное сложение через carry flag

Самое интересное — складываем два 32-битных числа, имея только 16-битные регистры:

```asm
; A = 0x0001_FFFF (DX=0x0001, AX=0xFFFF)
; B = 0x0000_0001 (CX=0x0000, BX=0x0001)
; Expected: 0x0002_0000  →  AX=0x0000, DX=0x0002
```

**Решение:**

```asm
_start:
    mov dx, 0x0001
    mov ax, 0xFFFF
    mov cx, 0x0000
    mov bx, 0x0001

    add ax, bx          ; младшие 16 бит: 0xFFFF + 1 = 0x0000, CF=1
    adc dx, cx          ; старшие: DX + CX + CF = 1 + 0 + 1 = 2
    hlt
```

`adc` (Add with Carry) добавляет ещё и текущий `CF`. Это базовый приём «multi-precision arithmetic», на котором построено всё сложение больших чисел в bignum-библиотеках.

## 10. Частые ошибки

| Симптом | Причина | Решение |
|---------|---------|---------|
| `nasm: command not found` | NASM не установлен | См. раздел 3.2 |
| Упражнение не зачитывается, хотя ассерты прошли | Не удалена строка `; I AM NOT DONE` | Удали её |
| `ASSERT_REG: AX == 0x1337 (got 0x0000)` | Не выполнилась нужная инструкция или ты пишешь не в тот регистр | Проверь, что `AX`, а не `BX` / `AL` |
| Бесконечный цикл / hang | Забыл `hlt` или условие выхода в `loop` | Добавь `hlt` в конец, перепроверь `CX` |
| Странные значения после `mul`/`div` | Результат / делимое в паре `DX:AX` | Учитывай старшее слово; перед `div` обнуляй `DX` |
| Условные переходы работают «наоборот» на знаковых | Используешь `jb`/`ja` вместо `jl`/`jg` | Для знаковых — `jl/jg`, для беззнаковых — `jb/ja` |
| `mov [bx], [si]` не компилируется | Память→память запрещено | Через регистр: `mov ax, [si]` → `mov [bx], ax` |
| Linker error `__atomic_compare_exchange_16` при установке | На Linux нет libatomic | `RUSTFLAGS="-Clink-arg=-latomic" cargo install asmlings` |

### 10.1 Как отлаживать упражнение

1. Перечитай комментарии в `.asm`-файле — там обычно уже лежит подсказка.
2. Запусти `asmlings run` — увидишь, какой именно ассерт упал и что фактически в регистрах.
3. Закомментируй последние строки и проверь промежуточное состояние.
4. Если эмулятор молчит — почти всегда виноват пропущенный `hlt`.


### 11.1 Быстрая таблица: какие флаги читает условный переход

| Инструкция | Условие | Использование |
|------------|---------|---------------|
| `je` / `jz` | ZF=1 | равно / ноль |
| `jne` / `jnz` | ZF=0 | не равно |
| `jb` / `jnae` / `jc` | CF=1 | беззнаковое < |
| `ja` / `jnbe` | CF=0 ∧ ZF=0 | беззнаковое > |
| `jl` / `jnge` | SF≠OF | знаковое < |
| `jg` / `jnle` | ZF=0 ∧ SF=OF | знаковое > |
| `js` | SF=1 | отрицательное |
| `jns` | SF=0 | неотрицательное |
| `jo` | OF=1 | знаковое переполнение |

## 12. Куда расти дальше

После 32 упражнений ASMLings у тебя будет фундамент, чтобы:

- 📖 *PC Assembly Language* — Paul A. Carter (бесплатный PDF) — лучшая «вторая книга».
- 📖 *The Art of Assembly Language* — Randall Hyde — фундаментально и подробно.
- 🔗 [felixcloutier.com/x86](https://www.felixcloutier.com/x86/) — справочник по всем x86-инструкциям с битовыми кодами.
- 🔗 [godbolt.org](https://godbolt.org) — Compiler Explorer: пишешь Rust/C — видишь сгенерированный ассемблер, инструкция в инструкцию.
- 🦀 **Rust + asm:** макрос `asm!` стабилен с Rust 1.59. Можно встраивать ассемблер в Rust-функции и звать его из safe-кода через `unsafe`-блок.
- 🔍 **Следующие архитектуры:** x86-64 (RAX/RBX, REX-префиксы, SSE/AVX) → ARM64 → RISC-V. Скачок 8086 → x86-64 минимален, потому что идеология одна.
- 🛠 **Реверс-инжиниринг:** Ghidra, Binary Ninja, radare2 — все три по умолчанию показывают код в x86-ассемблере, и теперь ты его читаешь.

### Пример: ассемблер прямо в Rust

```rust
use std::arch::asm;

fn add_via_asm(a: u64, b: u64) -> u64 {
    let mut result: u64;
    unsafe {
        asm!(
            "mov {0}, {1}",
            "add {0}, {2}",
            out(reg) result,
            in(reg)  a,
            in(reg)  b,
        );
    }
    result
}

fn main() {
    println!("{}", add_via_asm(40, 2));   // 42
}
```

Понимание 8086 — это ровно та база, с которой такой код перестаёт выглядеть как магия.
